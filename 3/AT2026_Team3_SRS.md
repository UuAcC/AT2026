# 1. Введение
[Обзор всего документа SRS.]

### 1.1 Цели
Целью разрабатываемой системы является автоматизация и наведение порядка в деятельности по согласованию различных типов документов (включая служебные записки, приходные и расходные договоры и т.д.) на предприятии. 
Внедрение системы предназначено для обеспечения проведения согласования в строгом соответствии с установленным регламентом, автоматической балансировки нагрузки между сотрудниками, сокращения времени, затрачиваемого на работу с документами, и прозрачности процесса электронного документооборота и адаптации системы под меняющиеся бизнес-процессы без необходимости доработки исходного кода.
## Границы применения
Разрабатываемое ПО является корпоративной системой для автоматизации процесса согласования договоров и других документов на предприятии. Система предназначена для регламентирования и сокращения времени согласования документов, а также для оптимизации хозяйственной деятельности предприятия. Система способна работать с приходными и расходными договорами, служебными записками и другими типами документов.

Система охватывает следующие основные этапы процесса:
* Инициирование согласования документа сотрудником предприятия.
* Выбор типа документа из перечня базовых или перманентных типов.
* Выбор стандартного маршрута согласования, связанного с выбранным типом документа, либо формирование собственного маршрута.
* Загрузка документа в систему.
* Формирование маршрута согласования из подразделений предприятия.
* Автоматическое распределение документов между сотрудниками соответствующих подразделений с учётом текущей нагрузки.
* Выбор вида согласования.
* Прохождение документом маршрута согласования.
* Обработка результатов, полученных на этапе прохождения маршрута согласования.
* Возврат документа инициатору при получении первого вердикта «не согласовано» (вместе с обязательным комментарием).
* Возможность повторного согласования изменённого документа.
* Учёт количества кругов согласования.
* Контроль сроков согласования и отображение информации о просрочивших согласование сотрудниках.
* Управление активностью сотрудников, участвующих в согласовании.
* Перераспределение задач деактивированных сотрудников между оставшимися активными сотрудниками соответствующих подразделений.
* Формирование отчётов о количестве обработанных документов каждым сотрудником за выбранный период.

Система должна обеспечивать получение и хранение сведений о сотрудниках предприятия, их подразделениях и статусе активности. Конкретный способ получения и актуализации этих сведений определяется на этапе проектирования.

Система предусматривает использование базовых типов документов и стандартных маршрутов согласования, встроенных в систему. Уполномоченные пользователи могут создавать перманентные типы документов и перманентные маршруты согласования, которые сохраняются в системе и доступны для последующего использования сотрудниками предприятия.

Система автоматизирует установленный по регламенту процесс согласования документов, но не определяет регламент.

Система не предусматривает участие в процессе согласования внешних по отношению к предприятию лиц.

Система не предусматривает никаких видов согласования, за исключением параллельного и последовательного.

Система не выполняет автоматический отказ в согласовании при превышении установленного времени обработки этапа. Информация о просрочке отображается инициатору, а дальнейшие действия выполняются вне системы.

Система предназначена для эксплуатации в локальной инфраструктуре предприятия.

## Термины и аббревиатуры
| **Термин/Аббревиатура** | **Определение** |
| --- | --- |
| Договор | Документ, заключение которого регламентировано на предприятии и подлежит согласованию в соответствии с установленным порядком. В системе классифицируются на приходные и расходные. |
| Тип документа | Классификатор документов. Для каждого типа может быть задано несколько стандартных маршрутов согласования. Список типов является расширяемым. |
| Стандартный тип документа | Тип документа, который изначально предустановлен в системе и не требует создания уполномоченным пользователем. |
| Перманентный тип документа | Тип документа, который создается уполномоченным пользователем в процессе настройки системы. |
| Инициатор | Сотрудник предприятия, который инициирует процесс заключения договора: выбирает тип документа и маршрут согласования, обрабатывает замечания при несогласовании. |
| Согласующий | Сотрудник предприятия, находящийся в составе подразделения, включенного в маршрут согласования. Изучает документ и выносит вердикт. |
| Уполномоченный пользователь | Сотрудник предприятия, обладающий расширенными правами: отвечает за формирование структуры (перманентных типов документов, перманентных шаблонов маршрутов). |
| Маршрут согласования | Упорядоченный список подразделений предприятия, которые должны обработать документ. Внутри подразделения документ распределяется между активными сотрудниками. Может быть стандартным (заданным для типа документа), перманентным (созданным уполномоченным пользователем) или индивидуальным. |
| Шаблон маршрута | Заранее определенный упорядоченный список подразделений (этапов), который используется для автоматического построения маршрута согласования конкретного типа документа. |
| Стандартный шаблон маршрута | Шаблон маршрута, который изначально предустановлен в системе для стандартных типов документов и не требует создания уполномоченным пользователем. |
| Перманентный шаблон маршрута | Шаблон маршрута, который создается уполномоченным пользователем для перманентных типов документов или индивидуальных нужд. |
| Балансировка нагрузки | Механизм автоматического распределения входящих документов между активными сотрудниками внутри подразделения для обеспечения примерно равного количества документов в работе у каждого. |
| Активный сотрудник | Сотрудник, находящийся в системе в статусе «активен» и способный получать документы на согласование. |
| Деактивированный сотрудник | Сотрудник, временно исключенный из процесса согласования. Его текущие задачи автоматически перераспределяются между оставшимися активными сотрудниками подразделения. |
| Круг согласования | Один полный цикл прохождения документа по маршруту согласования. |
| Последовательное согласование | Вид согласования, при котором каждое следующее подразделение получает документ только после обработки предыдущим. |
| Параллельное согласование | Вид согласования, при котором все подразделения из маршрута согласования получают документ одновременно. |
| Вердикт | Решение согласующего по документу. Принимает два значения: «согласовано» (комментарий не обязателен) или «не согласовано» (комментарий обязателен). |
| Согласованный договор | Договор, получивший вердикт «согласовано» от всех участников маршрута. |
| Несогласование | Ситуация, при которой хотя бы один участник вынес вердикт «не согласовано». Текущий круг завершается, документ снимается с остальных участников и возвращается инициатору. |
| Просрочка согласования | Ситуация, при которой сотрудник не вынес вердикт в установленный срок. Система помечает это в интерфейсе инициатора, но автоматический отказ при этом не срабатывает (дальнейшие действия — вне системы). |
| Регламент | Установленный на предприятии порядок заключения договоров, которому должна строго соответствовать работа системы. |
| Кадровая база | Внешняя информационная система предприятия с данными о сотрудниках и их принадлежности к подразделениям. |
| Отчёт по нагрузке | Документ, формируемый для руководителя, содержащий статистику о количестве обработанных документов каждым сотрудником за определенный период. |
| СТПО | Спецификация требований к программному обеспечению. Настоящий документ. |
| API | Программный интерфейс для обмена данными между системами. Используется для интеграции системы с кадровой базой. |
| Учётная запись | Запись в системе, идентифицирующая сотрудника и позволяющая ему войти в систему под своим именем. |
| Администратор системы | Сотрудник, отвечающий за настройку системы, управление учётными записями и сопровождение. |

## Краткий обзор

Настоящий документ представляет собой спецификацию требований к программному обеспечению (СТПО) системы автоматизации согласования документов на предприятии. Документ описывает назначение системы, её место в деятельности предприятия, характеристики пользователей, ограничения, а также детальные функциональные и нефункциональные требования.

Документ структурирован в соответствии с рекомендациями [IEEE-830] и состоит из четырёх основных разделов.

Раздел 1 «Введение» содержит цели создания документа, границы применения системы, определения ключевых терминов и аббревиатур, список использованных источников, а также настоящий краткий обзор.

Раздел 2 «Общее описание» описывает систему в целом: её описание изделия, функции, характеристики пользователей, ограничения, предположения и зависимости. Этот раздел не содержит детальных требований, а служит основой для их понимания в разделе 3.

Раздел 3 «Детальные требования» содержит полный перечень требований к системе. Подраздел «Функциональные требования» описывает процесс согласования документов: выбор типа документа, загрузку файла, выбор стандартного или собственного маршрута, формирование маршрута из подразделений, балансировку нагрузки между сотрудниками подразделения, выбор вида согласования, вынесение вердиктов, обработку несогласования, учёт кругов согласования, управление активностью сотрудников и отчётность, а также создание уполномоченными пользователями перманентных типов документов и перманентных шаблонов маршрутов, доступных всем пользователям наряду со встроенными стандартными. Остальные подразделы раздела 3 содержат нефункциональные требования: надёжность, производительность, ремонтопригодность, ограничения проекта, требования к пользовательской документации, используемые компоненты, интерфейсы, требования лицензирования и применимые стандарты. Каждое требование имеет уникальный идентификатор и атрибуты (приоритет, ссылки).

Раздел 4 «Индекс» содержит алфавитный указатель терминов и ссылок на разделы документа для облегчения навигации.

Документ предназначен для представителей заказчика, аналитиков, разработчиков, тестировщиков и менеджеров проекта.

# 2. Общее описание

## Описание изделия
Разрабатываемое ПО представляет собой корпоративную систему автоматизации согласования документов.

* **Интерфейсы системы**: подлежат выяснению.
* **Интерфейсы пользователя**: Система должна предоставлять интерфейс, позволяющий инициаторам загружать текст документа, выбирать его тип и маршрут согласования из подразделений, а согласующим — изучать документ и выносить вердикты. Также должен быть предусмотрены интерфейсы для руководителей для формирования и просмотра отчетов, а также для уполномоченных пользователей для создания новых перманентных типов документов и шаблонов маршрутов обхода.
* **Интерфейсы аппаратных средств ЭВМ**: подлежат выяснению.
* **Интерфейсы программного обеспечения**: Система должна обеспечивать периодическое получение сведений о сотрудниках и структуре подразделений из кадровой базы предприятия.
* **Интерфейсы коммуникаций**: подлежат выяснению.
* **Ограничения памяти**: подлежат выяснению.
* **Действия**: 
  * Создание/загрузка текста документа инициатором с обязательным указанием типа документа.
  * Формирование маршрута согласования из подразделений предприятия путем выбора сохраненного шаблона (соответствующего типу документа) или создания собственного маршрута.
  * Балансировка нагрузки при автоматическом распределении документов между сотрудниками внутри каждого подразделения.
  * Управление статусом сотрудника (активация/деактивация) с автоматическим перераспределением его задач между оставшимися сотрудниками подразделения при деактивации.
  * Маршрутизация документа по параллельному или последовательному виду согласования.
  * Сбор вердиктов («согласовано», «не согласовано») и комментариев (обязательных при вердикте «не согласовано») от сотрудников.
  * Автоматическое снятие документа с рассмотрения у остальных участников и возврат инициатору при первом отказе (вердикте «не согласовано») в цепочке.
  * Пометка в интерфейсе инициатора просрочившего сотрудника при превышении максимального времени на шаг (без автоматического отказа в согласовании).
  * Отслеживание и учет количества пройденных кругов согласования для каждого документа.
  * Формирование отчета для руководителя, отображающего количество обработанных документов каждым сотрудником за период.
  * Самостоятельное создание и сохранение в системе новых перманентных типов документов.
  * Создание и сохранение новых перманентных шаблонов (стандартных маршрутов) обхода персонала, состоящих из подразделений предприятия, и их привязка к определенным типам документов.
## Функции изделия
Система автоматизирует процесс согласования документов на предприятии и предоставляет следующие основные функции:

* **Управление типами документов и маршрутами согласования.** Система предоставляет встроенные базовые типы документов и стандартные маршруты согласования. Уполномоченный пользователь может создавать, редактировать и сохранять перманентные типы документов и перманентные маршруты согласования. Созданные сущности становятся доступными для последующего использования сотрудниками предприятия.

* **Инициирование согласования.** Инициатор выбирает тип документа из доступного перечня, выбирает стандартный маршрут согласования либо формирует собственный маршрут из подразделений предприятия, загружает документ и указывает вид согласования.

* **Формирование маршрута согласования.** Система формирует маршрут согласования на основании выбранного стандартного маршрута либо индивидуального маршрута, созданного инициатором.

* **Распределение нагрузки.** Система автоматически распределяет документы между активными сотрудниками соответствующих подразделений с учётом текущей нагрузки.

* **Обработка документов согласующими.** Согласующие изучают поступившие документы и выносят вердикты «согласовано» или «не согласовано». При несогласовании комментарий является обязательным.

* **Обработка результатов согласования.** Система обрабатывает результаты прохождения документа по маршруту. При несогласовании документ возвращается инициатору вместе с замечаниями для внесения изменений и повторного согласования.

* **Контроль процесса согласования.** Система обеспечивает учёт кругов согласования, контроль сроков обработки документов и отображение информации о просрочивших согласование сотрудниках.

* **Управление активностью сотрудников.** Система позволяет управлять статусами активности сотрудников и перераспределять незавершённые задачи деактивированных сотрудников между оставшимися активными сотрудниками соответствующих подразделений.

* **Формирование отчётности.** Система позволяет формировать отчёты о количестве обработанных документов каждым сотрудником за выбранный период.

Все пользователи системы делятся на четыре основные категории в зависимости от выполняемых функций и роли в процессе заключения договора:

## Ограничения

В данном подразделе приводится общее описание факторов, ограничивающих выбор разработчика. Ограничения сформулированы на основе исходного описания концепции системы.

**Ограничения по видам согласования**
- Система поддерживает только два вида согласования: последовательное и параллельное. Иные виды согласования в рамках данной концепции не рассматриваются.

**Ограничения по выбору вида и маршрута согласования**
- Выбор вида согласования возлагается на инициатора; иные способы выбора не рассматриваются.
- При запуске согласования инициатор обязан выбрать тип документа. После выбора типа документа ему отображаются доступные для этого типа стандартные и перманентные шаблоны маршрутов.
- Инициатор может выбрать один из доступных шаблонов маршрутов или запустить документ по собственному разовому маршруту; иные способы формирования маршрута не рассматриваются.
- Маршрут согласования формируется из подразделений предприятия; внешние участники не рассматриваются.
- Внутри каждого подразделения система выполняет балансировку нагрузки между сотрудниками: распределяет документы так, чтобы количество документов в работе у каждого сотрудника подразделения было примерно одинаковым.
- Система зависит от данных кадровой базы для формирования маршрутов согласования.

**Ограничения по типам документов и шаблонам маршрутов**
- Система должна содержать встроенные стандартные типы документов и стандартные шаблоны маршрутов согласования.
- Уполномоченные пользователи могут создавать, редактировать и сохранять перманентные типы документов и перманентные шаблоны маршрутов.
- Созданные перманентные типы документов и перманентные шаблоны маршрутов доступны всем пользователям наряду со встроенными стандартными сущностями.
- Количество типов документов и шаблонов маршрутов не фиксируется.
- Для каждого типа документа — встроенного или перманентного — может быть задано несколько стандартных или перманентных шаблонов маршрутов.
- Перманентные шаблоны маршрутов закрепляются за определёнными типами документов для многократного использования.
- Создание и изменение перманентных типов документов и перманентных шаблонов маршрутов не должно требовать доработки исходного кода системы.

**Ограничения по активации и деактивации сотрудников**
- Сотрудник может быть активирован или деактивирован, например на время отпуска или болезни.
- При деактивации сотрудника его задачи — документы на согласовании — перераспределяются между оставшимися сотрудниками соответствующего подразделения.

**Ограничения по вердиктам согласующих**
- Согласующий может вынести только два вердикта: «согласовано» или «не согласовано».
- При вердикте «не согласовано» комментарий обязателен.
- При вердикте «согласовано» комментарий может быть добавлен, но не является обязательным.

**Ограничения по условию согласования договора**
- Договор считается согласованным только в том случае, если его согласовали все участники маршрута.

**Ограничения по обработке несогласования**
- Если хотя бы один участник вынес вердикт «не согласовано», текущий круг согласования завершается в этот момент.
- Документ снимается с согласования у остальных участников, даже если они не успели его обработать.
- После несогласования инициатор получает сообщение, изменяет документ и отправляет его на следующий круг согласования.

**Ограничения по учёту**
- Количество кругов согласования по каждому документу отслеживается системой.

**Ограничения по времени на шаг согласования**
- Система должна поддерживать параметр «максимальное время на шаг» согласования.
- Автоматический отказ в согласовании по истечении этого времени отменяется.
- Вместо автоматического отказа система помечает в интерфейсе инициатора, что конкретный сотрудник просрочил согласование. Дальнейшие действия выполняются вне системы.

## Предположения и зависимости

Настоящий подраздел фиксирует факторы, которые не являются требованиями к системе, но влияют на них. Изменение любого из перечисленных ниже предположений или зависимостей может потребовать пересмотра требований, изложенных в разделе 3.

### Предположения

**Наличие кадровой базы.**
Предполагается, что на предприятии существует кадровая база, содержащая актуальные данные о сотрудниках (ФИО, должность, подразделение, статус) и организационной структуре предприятия. Система использует эти данные для формирования маршрутов согласования из подразделений, балансировки нагрузки и управления активностью сотрудников.

**Способ получения данных.**
Предполагается, что кадровая база предоставляет способ периодического получения сведений о сотрудниках, подразделениях и статусах активности (программный интерфейс, выгрузка, синхронизация). Конкретный способ определяется на этапе проектирования.

**Наличие регламента согласования.**
Предполагается, что на предприятии существует утверждённый регламент согласования документов, включая правила формирования маршрутов, сроки обработки и порядок вынесения вердиктов. Система автоматизирует этот регламент, но не заменяет его.

**Наличие уполномоченных пользователей для создания перманентных сущностей.**
Предполагается, что на предприятии определены пользователи, которым делегировано право создавать и изменять перманентные типы документов и перманентные шаблоны маршрутов. Созданные ими сущности сохраняются в системе и становятся доступны всем пользователям наряду со встроенными стандартными типами документов и шаблонами маршрутов. Система не определяет, кто именно является уполномоченным пользователем; это фиксируется в настройках ролей.

**Электронная форма документа.**
Предполагается, что текст документа, загружаемый инициатором в систему, представлен в электронной форме в виде файла. Система не выполняет распознавание сканированных бумажных документов.

**Наличие учётных записей.**
Предполагается, что все сотрудники, участвующие в согласовании (инициаторы, согласующие, руководители), зарегистрированы в системе и имеют учётные записи. Создание учётных записей выполняется администратором системы.

**Квалификация пользователей.**
Предполагается, что пользователи системы обладают базовыми навыками работы с компьютером и веб-браузером. Система не предназначена для пользователей без опыта работы с компьютером.

**Современный браузер.**
Предполагается, что на рабочих местах пользователей установлен современный веб-браузер, поддерживающий JavaScript. Конкретные версии браузеров определяются на этапе проектирования.

### Зависимости

**Зависимость от кадровой базы.**
Функционирование системы в части формирования маршрутов согласования, балансировки нагрузки и управления активностью сотрудников зависит от доступности и корректности данных кадровой базы. При изменении структуры или формата данных кадровой базы потребуется доработка модуля получения данных.

**Зависимость от регламента согласования.**
При изменении регламента согласования документов (например, изменении правил формирования маршрутов, сроков обработки или порядка вердиктов) может потребоваться изменение требований к системе.

**Зависимость от состава перманентных сущностей.**
При добавлении, изменении или удалении перманентных типов документов и перманентных шаблонов маршрутов уполномоченными пользователями может потребоваться актуализация настроек системы и проверка корректности связей между типами документов и шаблонами маршрутов. Система должна обеспечивать возможность таких изменений без доработки исходного кода и без влияния на встроенные стандартные сущности.

**Зависимость от законодательства.**
Требования к хранению, обработке и защите персональных данных сотрудников, используемых в системе, зависят от действующего законодательства. При изменении законодательства требования к системе могут быть пересмотрены.

**Зависимость от инфраструктуры.**
Работа системы зависит от наличия локальной вычислительной сети и серверного оборудования. Конкретные требования к инфраструктуре определяются на этапе проектирования.

* **Группа:** Управление маршрутизацией
* **Описание:** При поступлении документа на этап согласования в конкретное подразделение, система должна автоматически выполнять балансировку нагрузки, распределяя документы так, чтобы количество документов в работе у каждого сотрудника данного подразделения было примерно одинаковым.
* **Приоритет:** 1

**R1.03.05 Выбор вида согласования**
* **Группа:** Управление маршрутизацией
* **Описание:** Инициатор должен иметь возможность выбрать вид согласования при инициации документа: последовательное или параллельное.
* **Приоритет:** 1

**R1.03.06 Последовательное согласование**
* **Группа:** Управление маршрутизацией
* **Описание:** При выборе последовательного согласования система должна направлять документ в следующее подразделение по цепочке исключительно после того, как предыдущий этап обработки был полностью завершен.
* **Приоритет:** 1

**R1.03.07 Параллельное согласование**
* **Группа:** Управление маршрутизацией
* **Описание:** При выборе параллельного согласования система должна направлять документ сразу всем подразделениям, включенным в маршрут согласования.
* **Приоритет:** 1

#### 4. Управление согласованием (Обработка вердиктов)

**R1.04.01 Положительный вердикт**
* **Группа:** Управление согласованием
* **Описание:** Согласующий должен иметь возможность выбрать вердикт «согласовано». В этом случае система должна позволять (но не требовать) добавить к вердикту текстовый комментарий.
* **Приоритет:** 1

**R1.04.02 Отрицательный вердикт**
* **Группа:** Управление согласованием
* **Описание:** Согласующий должен иметь возможность выбрать вердикт «не согласовано». При выборе этого вердикта система должна требовать от пользователя обязательного ввода текстового комментария в свободной форме.
* **Приоритет:** 1

**R1.04.03 Прерывание круга согласования**
* **Группа:** Управление согласованием
* **Описание:** При получении вердикта «не согласовано» текущий круг завершается, документ автоматически снимается с рассмотрения у остальных участников маршрута и возвращается инициатору.
* **Приоритет:** 1

**R1.04.04 Уведомление об отказе**
* **Группа:** Управление согласованием
* **Описание:** При получении вердикта «не согласовано» система должна отправить инициатору соответствующее сообщение с комментарием, указанным согласующим.
* **Приоритет:** 1

**R1.04.05 Инициация нового круга**
* **Группа:** Управление согласованием
* **Описание:** После отклонения документа система должна предоставлять инициатору возможность внести изменения в документ и запустить его на следующий круг согласования.
* **Приоритет:** 1

**R1.04.06 Успешное завершение согласования**
* **Группа:** Управление согласованием
* **Описание:** Система должна устанавливать статус документа как окончательно согласованный только в том случае, если вердикт «согласовано» вынесли все участники маршрута согласования.
* **Приоритет:** 1

#### 5. Учет и отчетность

**R1.05.01 Отслеживание кругов согласования**
* **Группа:** Учет и отчетность
* **Описание:** Система должна вести автоматический учет количества кругов согласования по каждому документу, а также сохранять комментарии, сопровождавшие вердикты «не согласовано».

**R1.05.02 Отчетность для руководителя**
* **Группа:** Учет и отчетность
* **Описание:** Система должна предоставлять отчет, позволяющий руководителю просмотреть количество документов, которые обработал каждый сотрудник за выбранный период времени.
* **Приоритет:** 1

При формировании маршрута согласования актуальные данные о сотрудниках должны быть доступны не позднее чем через 3 секунды после запроса.

Привязка перманентных шаблонов маршрутов к типам документов должна изменяться без доработки исходного кода системы. * **Ссылается на:** R1.02.02; R1.03.03; R5.01.03

## Ограничения проекта

В данном подразделе приводятся ограничения, накладываемые на разработку системы. Ограничения сформулированы на основе требований к системе и внешних условий её функционирования.

**R5.01.01 Ограничения по интеграции с кадровой базой**
* **Группа:** Ограничения проекта\Интеграция
* **Описание:** Система должна обеспечивать периодическое получение сведений о сотрудниках, их принадлежности к подразделениям и статусах активности из кадровой базы предприятия. Кадровая база является внешней системой и не разрабатывается в рамках данного проекта. Изменение структуры или формата данных кадровой базы требует доработки модуля получения данных.
* **Приоритет:** 1
* **Ссылается на:** R1.01.01

**R5.01.02 Ограничения по форме документа**
* **Группа:** Ограничения проекта\Форма документа
* **Описание:** Документ поступает в систему в виде загружаемого файла. Система не проверяет соответствие документа шаблонам и не выполняет распознавание сканированных бумажных документов.
* **Приоритет:** 1
* **Ссылается на:** R1.02.01

**R5.01.03 Ограничения по типам документов и маршрутам**
* **Группа:** Ограничения проекта\Типы документов и маршруты
* **Описание:** Система должна содержать встроенные стандартные типы документов и стандартные шаблоны маршрутов согласования. Уполномоченные пользователи могут создавать и сохранять в системе перманентные типы документов и перманентные шаблоны маршрутов. Созданные уполномоченными пользователями перманентные сущности доступны всем пользователям наряду со встроенными стандартными. Количество типов документов и шаблонов маршрутов не фиксируется. Для каждого типа документа (встроенного или перманентного) может быть задано несколько стандартных или перманентных шаблонов маршрутов. Инициатор может выбрать доступный шаблон маршрута или сформировать собственный разовый маршрут из подразделений предприятия. Маршрут согласования формируется только из подразделений предприятия; внешние участники не рассматриваются.
* **Приоритет:** 1
* **Ссылается на:** R1.02.01; R1.02.02; R1.03.02; R1.03.03

**R5.01.04 Ограничения по процессу согласования**
* **Группа:** Ограничения проекта\Процесс согласования
* **Описание:** Система поддерживает только два вида согласования: последовательное и параллельное. Выбор вида согласования и формирование маршрута выполняются инициатором. Согласующий выносит только два вердикта: «согласовано» или «не согласовано». Документ считается согласованным только при согласовании всеми участниками маршрута. При первом вердикте «не согласовано» текущий круг завершается, документ снимается с остальных участников и возвращается инициатору. Внутри подразделения система выполняет балансировку нагрузки между сотрудниками.

Система должна работать в современном веб-браузере, поддерживающем JavaScript. Требований к операционной системе, СУБД, языку разработки и системному программному обеспечению в настоящем документе не устанавливается; их выбор определяется на этапе проектирования.

По истечении времени система помечает в интерфейсе инициатора, что сотрудник просрочил согласование; дальнейшие действия выполняются вне системы.

* **Группа:** Лицензирование\Совместимость
* **Описание:** Лицензии сторонних компонентов должны быть совместимы между собой и с условиями передачи системы заказчику. Они не должны препятствовать эксплуатации, сопровождению и развитию системы, а также не должны требовать раскрытия исходного кода системы или её проприетарных частей, кроме случаев, явно согласованных с заказчиком.
* **Приоритет:** 1
* **Ссылается на:** R9.01.01; R5.01.05

**R9.01.03 Реестр лицензий и лицензионная документация**
* **Группа:** Лицензирование\Документирование
* **Описание:** В состав эксплуатационной документации системы должен включаться реестр используемых сторонних компонентов и их лицензий с указанием наименования компонента, версии, типа лицензии, ограничений использования и источника получения. Реестр должен поддерживаться в актуальном состоянии при изменении состава компонентов системы.
* **Приоритет:** 1
* **Ссылается на:** R9.01.01; R6.01.01

**R9.01.04 Условия лицензирования разрабатываемой системы**
* **Группа:** Лицензирование\Передача прав
* **Описание:** Условия лицензирования разрабатываемой системы — объём передаваемых заказчику прав, территория и срок использования, порядок сопровождения и модификации — определяются договором между заказчиком и исполнителем. Система должна передаваться заказчику с правом использования для автоматизации согласования договоров на предприятии. Передаваемые права должны распространяться на использование встроенных и созданных уполномоченными пользователями перманентных типов документов и перманентных шаблонов маршрутов в рамках системы. Конкретная лицензия в настоящем документе не фиксируется и подлежит согласованию на этапе договора.
* **Приоритет:** 1
* **Ссылается на:** R5.01.05; R1.02.02; R1.03.03
